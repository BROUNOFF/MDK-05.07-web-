# GameTrack — трекер бэклога и каталога игр (веб-версия)

Веб-приложение на **React + Vite + Tailwind CSS**. Данные хранятся либо в браузере (по умолчанию),
либо в облачной базе **Supabase (PostgreSQL)** — переключение делается одним файлом `.env`.

Что умеет:

- вход и регистрация;
- дашборд: статистика, цель на год, «Играю сейчас» с кнопками +1 ч / −1 ч, рулетка бэклога;
- библиотека: фильтр по статусам, поиск, фильтр по платформе, сортировка;
- карточка игры: статус, платформа, оценка, часы, цена, стоимость часа, заметки, витрина, удаление;
- поиск игр (встроенный справочник или RAWG API) и добавление в библиотеку;
- статистика: время по жанрам и платформам, карта активности, 8 достижений, самые выгодные покупки;
- профиль: имя, цель на год, топ-5 любимых игр.


## 1. Запуск на своём ПК (Windows)

### Шаг 1. Проверить Node.js

Открой **Командную строку** (Пуск → набери `cmd` → Enter). Именно cmd, а не PowerShell —
в PowerShell у тебя уже была ошибка «выполнение сценариев отключено».

```
node -v
```

Если появилась версия вида `v20...` или `v22...` — всё хорошо.
Если написано «не является внутренней командой» — скачай **LTS** с https://nodejs.org, установи
(везде «Далее»), закрой и заново открой cmd.

### Шаг 2. Распаковать проект

1. Если у тебя уже есть папка `C:\NodeJS\gametrack-web` со старым MVP — переименуй её в
   `gametrack-mvp` (пусть останется для отчёта).
2. Распакуй архив `gametrack-web.zip` в `C:\NodeJS\`.
   Должно получиться `C:\NodeJS\gametrack-web\`, а внутри сразу файлы `package.json`, `index.html` и папка `src`.

### Шаг 3. Установить библиотеки (один раз)

```
cd C:\NodeJS\gametrack-web
npm install
```

Займёт 1–2 минуты, появится папка `node_modules`.
Жёлтые строчки `npm warn` и сообщение про `vulnerabilities` — это нормально.
**Не запускай** `npm audit fix --force` — он обновит пакеты до несовместимых версий.

### Шаг 4. Запустить

```
npm run dev
```

Браузер сам откроет http://localhost:5173. Если не открыл — скопируй адрес из консоли.

### Шаг 5. Войти

На странице входа нажми **«Подставить данные»** → **«Войти»**.
Это демо-аккаунт `demo@gametrack.ru` / `demo123` с уже заполненной библиотекой.
Можно также зарегистрировать свой аккаунт — он будет пустым, и на дашборде появится кнопка
«Заполнить демо-данными».

Остановить сервер: в окне cmd нажми **Ctrl + C**.
В следующий раз достаточно шагов `cd C:\NodeJS\gametrack-web` и `npm run dev`.

> Пока Supabase не подключён, данные лежат в localStorage браузера: они сохраняются между запусками,
> но только в этом браузере. Чтобы начать с чистого листа: F12 → Application → Local Storage →
> удалить ключ `gametrack-db`.


## 2. Как устроен проект

```
gametrack-web/
├── index.html               — HTML-страница, в которую React рисует приложение
├── package.json             — список библиотек и команды (dev, build)
├── .env.example             — образец настроек для Supabase и RAWG
├── supabase/schema.sql      — SQL-скрипт: таблицы и права доступа в Supabase
└── src/
    ├── main.jsx             — точка входа, подключает контексты и стили
    ├── App.jsx              — маршруты (какой адрес → какая страница)
    ├── index.css            — Tailwind и общие классы (.btn, .card, .input)
    ├── api/
    │   ├── index.js         — выбирает, откуда брать данные: Supabase или localStorage
    │   ├── localDb.js       — хранение в браузере (работает без интернета)
    │   ├── supabaseDb.js    — те же функции, но через облачную БД
    │   └── gamesSearch.js   — поиск игр: RAWG API или встроенный справочник
    ├── context/
    │   ├── AuthContext.jsx    — кто вошёл в систему
    │   ├── LibraryContext.jsx — библиотека, сессии, цель на год и действия с ними
    │   └── ToastContext.jsx   — всплывающие уведомления
    ├── data/
    │   ├── catalog.js       — встроенный справочник (35 игр)
    │   └── demoData.js      — демо-библиотека
    ├── utils/
    │   ├── stats.js         — формулы из ТЗ: стоимость часа, % цели, доли жанров, рулетка
    │   ├── achievements.js  — правила достижений
    │   ├── constants.js     — статусы и платформы
    │   └── date.js          — работа с датами
    ├── components/          — повторяющиеся части интерфейса (меню, обложка, модальные окна, heatmap)
    └── pages/               — страницы: Login, Dashboard, Library, GameDetail, Search, Stats, Profile
```

Главная идея архитектуры: страницы не знают, где лежат данные. Они вызывают функции из `src/api`,
а `api/index.js` сам решает — работать с localStorage или с Supabase. Поэтому подключение базы
не требует переписывать интерфейс.


## 3. Подключение Supabase (когда понадобится)

1. Зарегистрируйся на https://supabase.com и нажми **New project** (регион любой, пароль БД запиши).
2. Слева **SQL Editor** → **New query** → вставь всё содержимое файла `supabase/schema.sql` → **Run**.
   Должно появиться `Success`. В **Table Editor** появятся таблицы `games`, `user_games`,
   `game_sessions`, `yearly_goals`.
3. **Authentication → Sign In / Providers → Email**: выключи **Confirm email** и сохрани.
   Так при регистрации не нужно будет подтверждать почту (для учебного проекта удобнее).
4. **Project Settings → API** (или кнопка **Connect**): скопируй **Project URL** и ключ
   **anon public** (в новых проектах он называется **Publishable key**).
5. В папке проекта сделай копию файла `.env.example` и назови её `.env`. Заполни:
   ```
   VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
   VITE_SUPABASE_KEY=скопированный_ключ
   ```
6. Останови сервер (Ctrl + C) и снова запусти `npm run dev` — Vite читает `.env` только при старте.
7. Зарегистрируйся на сайте, нажми «Заполнить демо-данными». Внизу бокового меню будет надпись
   «Supabase (PostgreSQL)», а записи появятся в Table Editor.

Каждый пользователь видит только свои игры — за это отвечают политики Row Level Security в `schema.sql`.


## 4. Подключение RAWG API (по желанию)

Без ключа поиск работает по встроенному справочнику. С ключом — по базе rawg.io с настоящими обложками.

1. Зарегистрируйся на https://rawg.io/apidocs и получи бесплатный API key.
2. Впиши его в `.env`: `VITE_RAWG_KEY=твой_ключ`
3. Перезапусти `npm run dev`.


## 5. Если что-то не работает

| Проблема | Что сделать |
|---|---|
| `npm : Невозможно загрузить файл ... npm.ps1` | Ты в PowerShell. Открой обычную cmd или выполни `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| `Could not read package.json` | Ты не в той папке. Выполни `cd C:\NodeJS\gametrack-web` (там, где лежит package.json) |
| `Port 5173 is in use` | Уже запущен другой сервер. Закрой старое окно cmd или открой адрес, который Vite написал вместо 5173 |
| Белый экран | Нажми F12 → вкладка Console, там будет текст ошибки |
| Изменил `.env`, а ничего не поменялось | Перезапусти сервер: Ctrl + C, затем `npm run dev` |
| В VS Code красным подчёркнут импорт | Проверь, что файл сохранён (Ctrl + S), или Ctrl + Shift + P → Reload Window |


## 6. Сборка для сдачи / Docker

```
npm run build
```

Готовый сайт появится в папке `dist` — это обычные HTML, CSS и JS, их можно положить на любой хостинг
или в Docker-контейнер с Nginx.
